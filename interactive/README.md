# Interactive Component

This component is based off our existing versions of HealthPAL, with some variation. First, the actual HealthPAL is currently restricted to only out clinical trials and approved collaborators through IRB. Also, the clinician-facing site is also in development, meaning there is not a de-facto UI for this. So, we instead created a Python Flask App to display how a clinician may use these tools.

## Description of Design

We currently open on the home page, where the user can then login. Since this is not the actual HealthPAL app, the login page is just mocked up, and requires no credentials for now. After login, the "clinician" can upload a transcript, after which it is processed after upload. This breaks down each part individually, first showing some visuals for speaking time, and a breakdown of who is speaking through the visit. The next tab shows the dialogue acts broken down by speaker, and upon selecting a certain DA, will highlight turns with those DAs on the left.

The design is loosely based on the existing research-coordinator view of the HealthPAL frontend, ported from typescript over to python flask. Still, many of the templates (`base.html`, `login.html`, `home.html`, `visit.html`) are lifted directly from HealthPAL, with some modified more than others (for example, `visit.html` has been modified pretty heavily). This did drop out some parts  That part is dependent on who is actually recording the session, which if this were to go through clinical trials, would likely start as the research coordinator anyways, not the clinician at first.

The CSS and js scripts were for the most part lifted directly from HealthPAL, with some minor additions for the styling of the modified clinician page and the modified visits page.

## Data considerations

The data used within this project is, once again, restricted under IRB. So, we instead provide some sample transcripts to use with the tool, that were generated using LLMs. The code and generated transcripts are given within the `generate_transcript` folder. Considering these are generated by LLMs for the purpose of being for a demo, these should not be analyzed in a given way, realistic conversation is a lot different than what the LLMs generate.

## Pieces of the functional component

The overall workflow includes the following below. 

- Visit Summary Statistics. This uses basic speaker statistics (who is speaking for how long, etc) (the below two items are ways to interact with some of the features we extracted directly, to give context to each of these features).
    - Dialogue Act Statistics. An interactive component to view who is asking questions, etc, during a visit.
    - Embedding/Repetition Measures. An interactive component for viewing where repetition is happening during a visit, and by who.
- Dementia Severity Prediction. Along with the base DSRS score, this page would include some interpretations of the severity scaling that typically occurs after the DSRS is predicted. 

## App

We use a Flask app. It's UI is made to look similar to that of HealthPAL, but considering there is no existing clinician-facing side of this right now, this is open for some interpretation by us.

So, this includes an area to select patients. The generate_transcripts will generate 3 different patients, of varying severity. These show in the UI, where after "logging in," each patient can be selected. Within this, a transcript of the visit, and the other pieces from above are shown (typically we prefer to show an audio recording to patients/caregivers, but since this demo is using generated transcripts, transcripts it will be).

Run the app using `flask --app app run`, from within the app dir. Be careful with your venv, you may want to create a conda environment for this (using requirements.txt from the above dir).

Note, I did have some issues with my venv not recognizing the correct flask to run, so I had to run `../../.venv/bin/flask --app app run`, from within the app folder

## AI usage in Flask app

Claude Sonnet 5.5 was used for porting over some existing HealthPAL logic from typescript into flask, and helping to setup some endpoints. Sonnet was also used to help setup the frontend, using the scripts provided in `app/pipeline/`. 

We also had Claude setup a synthetic generation pipeline, as seen in `generate_transcript/generate_transcript.py`, which uses the Dartmouth langchain api to generate example sessions, surrounding a brief description of a patient, dementia severity, etc. Three pre-generated transcripts are given in `generate_transcript/synthetic_transcript/`. Considering we weren't using the generated transcripts for anything other than the interactive demo, we felt as though the heavier AI usage on that script was acceptable under the AI policy for the course project.
